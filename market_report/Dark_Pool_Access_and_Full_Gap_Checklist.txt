PART 1 — FINRA ACCESS INSTRUCTIONS: S&P 100 DARK POOL SENTIMENT GAUGE
================================================================

GOAL: A market-wide dark-pool sentiment gauge (DIX-style), scoped to the
S&P 100, updated daily (T+1), built entirely on free FINRA data. Lives on
the Sentiment tab next to Fear & Greed and Put/Call.

WHAT THIS IS BUILT ON
The gauge is the dollar-weighted ratio of short volume to total volume in
off-exchange trading, summed across the S&P 100. This is the same raw
methodology SqueezeMetrics uses for DIX (dollar value of short volume
across the index, divided by total dark-pool dollar volume) — the
$720/month product and this free build use the same underlying regulatory
data. Market makers filling customer sell orders in a dark pool get
recorded as short sales even though the market maker is buying, so a
higher ratio reads as more dark-pool buying being absorbed (bullish),
consistent with SqueezeMetrics' "short is long" framing.

STEP 1 — Register a FINRA Developer account
- Go to developer.finra.org
- Create an Individual API User Account (no firm affiliation needed —
  this path is explicitly supported for exactly this use case: testing
  and building before/without a firm SAA relationship)
- Provision a PUBLIC credential type, not Mock or Firm. Public credentials
  access publicly available FINRA data at no cost, capped at 10 GB of
  data download per month. That cap is not a real constraint here — a
  daily pull across 100 tickers is a trivial fraction of it.
- You'll receive an API Client ID by email, then activate the credential
  and set a client secret. Note: the activation link expires in 24 hours.

STEP 2 — Authenticate (OAuth2)
- Token endpoint: https://ews.fip.finra.org/fip/rest/ews/oauth2/access_token
- Standard OAuth2 client-credentials flow using your Client ID/Secret
- Tokens are short-lived; the pull script needs to fetch a fresh token
  each run, not cache one long-term

STEP 3 — Pull the Reg SHO Daily Short Sale Volume dataset
- Dataset landing page: developer.finra.org/docs/reg-sho-daily-short-sale-volume
- Full dataset catalog (to confirm exact group/dataset name and request
  schema before writing the pull): developer.finra.org/catalog
- FINRA's Query API pattern (confirmed from other FINRA datasets, same
  general shape expected here): a POST request with a JSON body
  specifying dateRangeFilters (start/end date), an optional symbol
  filter, and limit/offset for pagination. CONFIRM the exact endpoint
  path and payload shape against the docs page above before building —
  I have the general access pattern confirmed but not the literal
  endpoint string for this specific dataset verified end-to-end, and
  guessing at it risks a silent-fail integration. Check the docs page
  first; do not assume the path from other FINRA datasets carries over
  unchanged.
- The file returns, per security per day: total volume, short volume,
  short exempt volume, and which reporting facility (NYSE TRF, NASDAQ
  TRF Carteret, NASDAQ TRF Chicago, or ADF) it came from. Sum across
  facilities per ticker per day for a consolidated short volume figure.
- Data is published the next business day (T+1) — same cadence
  SqueezeMetrics itself runs on, so no speed disadvantage versus the
  paid product.

STEP 4 — Get the S&P 100 constituent list
- The S&P 100 changes rarely (a handful of times a year at most). Don't
  build a live constituents feed — that's solving a problem that
  doesn't exist yet. Maintain a static list of the ~101 tickers, sourced
  once from a reliable public list (Wikipedia's "S&P 100" page is
  commonly used for this and is kept current), and update it manually
  or on a quarterly review cadence.

STEP 5 — Get daily close prices for dollar-weighting
- Pull daily close price per ticker from the existing yfinance pipeline
  already in use for sector ratios — no new data source needed here.
- Dollar-weighting note: you do NOT need separate market-cap weights.
  Converting share volume to dollar volume (price x volume) and summing
  short-dollar-volume over total-dollar-volume across all 100 names
  IS the dollar-weighting — larger, more heavily-traded names
  automatically carry more weight in the ratio. This matches
  SqueezeMetrics' own methodology description.

STEP 6 — Compute the daily ratio
  Raw ratio (per day) = SUM(short_dollar_volume across S&P 100)
                         / SUM(total_dollar_volume across S&P 100)
  short_dollar_volume(ticker) = short_volume(ticker) x close_price(ticker)
  total_dollar_volume(ticker) = total_volume(ticker) x close_price(ticker)

STEP 7 — Normalize (decision point, not fully resolved — validate before
committing)
- The raw ratio is NOT a clean bounded/self-normalizing series the way
  CMF is treated elsewhere in the stack. SqueezeMetrics notes the raw
  ratio drifts over multi-year periods due to structural changes in
  market microstructure (HFT proliferation), which is why they run it
  through a hyperbolic tangent (tanh) normalization over a rolling
  1-year window rather than displaying it raw.
- Two candidate approaches: (a) tanh normalization over trailing 1-year,
  matching SqueezeMetrics' own method, or (b) percentile rank over
  trailing 1-year, consistent with how right-skewed series are already
  handled elsewhere in the stack. Backtest both against known regime
  turns before picking one — this has not been validated yet.

STEP 8 — Known limitation (inherited by any version of this metric, paid
or free — flag this, don't treat it as a defect of the free build)
- Practitioners have documented DIX-style signals under-reading
  bullishness during 2024-2025 stretches because the explosive growth in
  0DTE options volume means market makers increasingly hedge using
  futures or ETFs instead of single stocks. A short-volume ratio built
  from single-name data doesn't see that hedging flow. Treat this gauge
  as one pillar of context, same discipline as everything else in the
  stack — not a standalone signal.

WHERE THIS GOES
Sentiment tab, alongside Fear & Greed and Put/Call. Not a per-ticker
tool — this is explicitly a market-wide gauge per the S&P 100 scope
decision, not a replacement for per-name dark pool context.

PART 2 — FULL GAP CHECKLIST FROM STOCKCHARTS COMPARISON
================================================================
(Carrying all items forward, not narrowed to a subset)

[ ] 1. Build a Breadth panel on the Overview tab
    Reasoning: Largest single gap found. StockCharts runs breadth as a
    top-level category (Advance/Decline %, % above 50/200-day MA,
    Bullish Percent Index, New Highs/Lows). This dashboard has none of
    it anywhere on the web — it currently lives only inside TOS as a
    Regime Classifier v2 pillar. Build the core two only: Advance/
    Decline % and % of S&P 500 above 50-day and 200-day MA. Skip
    Bullish Percent Index and the six-timeframe new-highs/lows table —
    diminishing returns on a third and fourth view of the same
    underlying breadth question. This is the same $SPXA50R-type data
    already feeding the Regime Classifier, so it's a second display
    surface, not new data engineering. Place near the top of Overview —
    it's the highest-frequency item on the existing pre-market checklist
    that isn't on the web dashboard at all.

[ ] 2. Add NAAIM Exposure Index to the Sentiment tab
    Reasoning: Weekly survey of active fund managers' actual long
    equity exposure — the professional-money counterpart to AAII.
    Free, weekly. StockCharts treats this as a standard sentiment
    component; this dashboard has no professional-positioning read at
    all right now, only retail-adjacent (Fear & Greed) and options-
    adjacent (Put/Call) reads.

[ ] 3. Add AAII Bulls-Bears survey to the Sentiment tab
    Reasoning: Free weekly retail sentiment survey, dates to 1987,
    referenced repeatedly across independent sources as a standard
    dashboard component. Pairs directly with NAAIM (item 2) for the
    classic contrarian setup: retail euphoric while professional money
    is already de-risking. Neither half of that pair currently exists
    on this dashboard.

[ ] 4. Replace/supplement the HYG price line with High Yield OAS spread
    Reasoning: Sharpens the credit gap flagged in the prior sprint
    checklist (item 5 there was just "add HYG"). StockCharts uses the
    ICE BofA High Yield Option-Adjusted Spread ($$HYIOAS / FRED series
    BAMLH0A0HYM2), not raw HYG price. OAS isolates credit risk
    repricing from rate moves, which raw HYG price can't cleanly
    separate — this is the more precise version of what the pre-market
    checklist's "Check Credit: HYG trending" item is actually asking
    for. Sourceable from FRED, same place already used for Treasury
    yields on the Fed & Economic tab.

[ ] 5. Add equal-weight sector overlay to the Sector Ratios tab
    Reasoning: Currently shows sector/SPY ratio, effectively cap-
    weighted. StockCharts shows sectors three ways (cap-weight, equal-
    weight, small-cap) specifically to reveal whether a sector's
    strength is broad or concentrated in one or two mega-caps — this is
    breadth applied at the sector level, and it's a direct extension of
    the existing RS Z-score philosophy already in the indicator stack.
    Cheap to add: equal-weight sector ETFs (RSPT, RSPH, etc.) are on
    Yahoo Finance same as the cap-weight ones already pulled.

[ ] 6. Complete the Economic panel with a broader indicator set
    Reasoning: Ties to the "confirm Overview tab is actually populated"
    item from the prior checklist. If the Economic Snapshot / Economic
    Indicators sections are being built from scratch, StockCharts'
    panel is a useful target spec: GDP, CPI, PPI, Leading Economic
    Index, Unemployment, Housing Starts, Existing Home Sales,
    Manufacturing PMI, Services PMI, Industrial Production — each with
    a 12-month rate-of-change overlay. The Leading Index in particular
    is forward-looking, a genuinely different signal than the trailing
    prints currently listed in the table headers.

[ ] 7. Finish the Overview tab's Dollar & Commodities section with
    cross-asset/intermarket framing
    Reasoning: Same underlying gap as the prior checklist's item 4
    (confirm Overview tables populate), now with a clearer target spec.
    StockCharts runs a dedicated intermarket panel — stocks, bonds,
    commodities, currencies plotted together (SPY, TLT, DBC, USO, GLD,
    UUP) — because cross-asset relationships matter more than any one
    asset class alone. Don't build this as a separate tab; finish the
    already-planned Dollar & Commodities section with this framing:
    add a bond proxy (TLT) and a broad commodities index alongside
    what's already there.

[ ] 8. (Lower priority — optional) Market Factors heat map
    Reasoning: Growth vs. value, small/mid/large cap, low-vol vs. high-
    beta performance. Real signal, but it's a portfolio-construction
    lens more than an entry-timing one, and doesn't map onto any
    existing gate in the Macro Permission Hierarchy the way breadth and
    credit do. Build after the above, not before.

PART 3 — LAYOUT CHANGES
================================================================

TAB ORDER
Current: Overview -> Fed & Economic -> Fed Dashboard -> Sentiment ->
Sector Ratios
Recommended: Overview -> Sentiment -> Sector Ratios -> Fed & Economic
-> Fed Dashboard
Reasoning: fastest-changing, most decision-relevant data leads;
slowest-moving macro backdrop trails. Sentiment and breadth move daily
and feed same-day reads; Fed & Economic moves on a release schedule.
Checking Fed & Economic before Sentiment doesn't match how often either
one actually changes. Fed Dashboard is explicitly context-only and
already sits last, correctly.

WITHIN-TAB PLACEMENT FOR NEW ITEMS

Overview tab:
- Breadth panel goes at the top, directly under or beside the index
  levels — it's the highest-frequency item on the existing pre-market
  checklist that isn't on the web at all, so it shouldn't be buried
  below slower-moving content.
- Dollar & Commodities / intermarket completion sits below breadth.
- Economic Snapshot completion sits below that — it's the slowest-
  moving content on this tab and belongs at the bottom of the page,
  not competing with breadth and indices for the first glance.

Sentiment tab — needs sub-grouping, not just more rows:
Adding NAAIM, AAII, and the dark pool gauge on top of the existing
Fear & Greed, Consumer Sentiment, Put/Call, and Claude Report brings
this tab to seven sections flat. That defeats the point of a fast
morning scan. Split into two visual groups on the same tab:
  - "Positioning" group: NAAIM, AAII, Dark Pool gauge — these are all
    flow-of-funds / who's-actually-buying reads, updated daily or
    weekly.
  - "Volatility & Options" group: VIX/Fear & Greed, Put/Call — these
    are option-market-derived reads, updated intraday/daily.
Keep Claude Report and Consumer Sentiment outside both groups as
standalone items, same as today.

Fed Dashboard tab — correction to earlier assumption:
The HY OAS spread (item 4) does NOT belong on the Fed & Economic tab
next to Treasury yields. Fed Dashboard already has an empty Tier 3
slot literally labeled "Financial Conditions & Credit" ("Being built
out line by line — check back soon"). That's the built-for-purpose
home for OAS and HYG — use the slot that already exists instead of
adding a new section elsewhere.

Sector Ratios tab:
Add the equal-weight overlay (item 5) as a toggle next to the existing
Sector/SPY Ratio panel, not as a separate row underneath. The value of
cap-weight vs. equal-weight is in comparing them directly — a toggle
keeps that a single visual comparison instead of two panels the eye
has to jump between.

Fed & Economic tab:
Economic panel completion (item 6) goes in the existing "Economic
Indicators" section on this tab — no placement change needed, just
population.

Market Factors heat map (item 8, optional/low priority): no placement
decision yet — revisit if and when this gets greenlit.
